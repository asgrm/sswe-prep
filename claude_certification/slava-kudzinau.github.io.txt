MCP Configuration Example
  User MCP servers are configured in ~/.claude.json:

  {
    "mcpServers": {
      "gdrive": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-gdrive"],
        "env": {
          "GOOGLE_OAUTH_TOKEN": "${GDRIVE_TOKEN}"
        }
      }
    }
  }

  Project MCP servers are configured in .mcp.json (project root):

  {
    "mcpServers": {
      "jira": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-jira"],
        "env": {
          "JIRA_URL": "https://company.atlassian.net",
          "JIRA_API_TOKEN": "${JIRA_TOKEN}"
        }
      }
    }
  }

  Note: The JSON examples above show the configuration structure generated by CLI commands. For most use cases, use claude mcp add


AWS Bedrock Authentication
  Prerequisites:

  AWS account with Bedrock access
  AWS CLI configured
  Setup:

  # Configure AWS credentials
  aws configure

  # Set AWS region
  export AWS_REGION=us-east-1

  # Test with Claude
  claude --platform bedrock "test message"

  Configuration file (.claude/config.json):

  {
    "platform": "bedrock",
    "aws_region": "us-east-1",
    "aws_profile": "default"
  }

Adding mcp server

  # Add HTTP server (cloud services - recommended)
  claude mcp add --transport http github https://api.githubcopilot.com/mcp/


  # With authentication
  claude mcp add --transport http sentry https://mcp.sentry.dev/mcp \
    --header "Authorization: Bearer ${SENTRY_TOKEN}"

  # With custom headers
  claude mcp add --transport http notion https://mcp.notion.com/mcp \
    --header "Notion-Version: 2022-06-28" \
    --header "Authorization: Bearer ${NOTION_TOKEN}"

  # Add stdio server (local processes)
  claude mcp add --transport stdio gdrive \
    --env GOOGLE_TOKEN="${GDRIVE_TOKEN}" \
    -- npx -y @modelcontextprotocol/server-gdrive

  # With working directory
  claude mcp add --transport stdio custom \
    --cwd /path/to/server \
    -- node server.js

  # Windows: Use cmd /c before npx
  claude mcp add --transport stdio gdrive \
    -- cmd /c npx -y @modelcontextprotocol/server-gdrive

  SSE Transport (Deprecated):

  # Server-Sent Events (legacy support only)
  claude mcp add --transport sse asana https://mcp.asana.com/sse \
    --header "X-API-Key: ${ASANA_KEY}"

MCP Managed scope locations:


  Selecting Scope with CLI
  # Local scope (default - personal, this project only)
  claude mcp add --scope local custom https://api.company.com/mcp

  # Project scope (team-shared, in .mcp.json)
  claude mcp add --scope project jira \
    -- npx -y @modelcontextprotocol/server-jira

  # User scope (personal, all projects)
  claude mcp add --scope user gdrive \
    -- npx -y @modelcontextprotocol/server-gdrive


MCP config structure
  {
      "mcpServers": {
          "jira": {
              "command": "npx",
              "args": [
                  "-y",
                  "@modelcontextprotocol/server-jira"
              ],
              "env": {
                  "JIRA_URL": "https://company.atlassian.net",
                  "JIRA_EMAIL": "${JIRA_EMAIL}",
                  "JIRA_API_TOKEN": "${JIRA_TOKEN}"
              }
          },
          "internal-api": {
              "command": "npx",
              "args": [
                  "-y",
                  "@company/mcp-server-internal"
              ],
              "env": {
                  "API_KEY": "${INTERNAL_API_KEY}",
                  "TIMEOUT": "${REQUEST_TIMEOUT:-5000}",
                  "ENDPOINT": "${API_ENDPOINT:-https://api.internal.company.com}"
              }
          }
      }
  }

  Never commit credentials to .mcp.json
  Use ${VAR} syntax in configuration
  Use specific package versions for stdio: npx -y package@1.2.3


  ${VAR} means the variable is REQUIRED. If it is not set, the server fails to start.
  ${VAR:-default} means the variable is OPTIONAL. If it is not set, the default value after ":-" is used instead.


  there is a common practice regarding env
    Fill in your credentials in .env

    Load environment:
    source .env  # macOS/Linux

If allowed-tools is missing from a SKILL.md, it means all tools are allowed — not none.

Skill Frontmatter Options
  name - Unique identifier (required)
  description - What the skill does and when to use it (required)
  disable-model-invocation - Restricts skill to manual/user-only invocation via slash command, Claude cannot auto-trigger it (optional)
  user-invocable - Restricts skill to Claude-only invocation, hides it from slash commands (optional)
  allowed-tools - Pre-approves listed tools so Claude doesn't prompt for permission each time; NOT a hard restriction, not reliably enforced everywhere (optional)
  context - Sets execution context; context: fork runs the skill in an isolated subagent with its own context window (optional)
  agent - Specifies which subagent configuration to use, typically paired with context: fork (optional)
  model - Which model runs while the skill is active; accepts aliases (sonnet, opus, haiku) or "inherit" for the main conversation's model (optional)
  argument-hint - Hints at what input/arguments to provide when invoking the skill (optional)


Store user skills in ~/.claude/skills/
Store project skills in .claude/skills/

Creating Custom Plugins
  my-plugin/
  ├── .claude-plugin/
  │   └── plugin.json
  ├── skills/
  │   └── skill1/SKILL.md
  ├── agents/
  │   └── agent1.md
  ├── hooks/
  │   └── hooks.json
  ├── .mcp.json
  ├── settings.json
  └── README.md

  plugin.json
  {
    "name": "my-plugin",
    "version": "1.2.0",
    "description": "...",
    "author": { "name": "Your Name", "email": "you@example.com" },
    "license": "MIT",
    "homepage": "https://github.com/user/plugin",
    "keywords": ["typescript", "node"],
    "hooks": "./hooks",
    "mcpServers": "./.mcp.json"
  }

  Publishing: push to a git repo → create a .claude-plugin/marketplace.json catalog (own repo or submit to official marketplace) → users run /plugin marketplace add owner/repo then /plugin install plugin-name@marketplace-name.
